Memoria (CLAUDE.md), Skills y Comandos Personalizados

1. ¿Qué es el archivo CLAUDE.md y por qué es tan importante?

En el ecosistema de Claude, el archivo CLAUDE.md cumple exactamente la misma misión que GEMINI.md en Antigravity: es la memoria permanente de tu proyecto. Cada vez que abres Claude Code en tu carpeta de trabajo, lo primero que hace de forma automática es leer el archivo CLAUDE.md e inyectar sus instrucciones en su memoria antes de que escribas la primera palabra.

Como vimos en el apartado de comandos /, no necesitas siquiera escribir este archivo desde cero: basta con ejecutar /init para que Claude analice tu repositorio y cree un primer borrador completo que luego puedes retocar con /memory o añadiendo notas rápidas con el prefijo #.

1.1. Jerarquía de archivos de memoria en Claude

Archivo y Ruta ¿Se sube a Git? Para qué sirve cada uno
~/.claude/CLAUDE.md No (está en tu carpeta de usuario) Memoria Global Personal: Tus gustos personales para todos los proyectos de tu ordenador (ej. "Respóndeme siempre en español y explica los cambios").
./CLAUDE.md Sí (compartido con el equipo) Memoria del Proyecto: Arquitectura de carpetas, cómo añadir nuevas vistas y componentes, clases CSS obligatorias y comandos habituales.
./CLAUDE.local.md No (se ignora en Git) Memoria Local Privada: Rutas o notas específicas de tu máquina para este proyecto que no quieres subir al repositorio compartido.
.claude/rules/*.md Sí (opcional y modular) Reglas Modulares: Permite dividir las normas de un proyecto grande en varios archivos pequeños dentro de .claude/rules/.

2. Cómo crear tus propios Comandos con / (.claude/commands/)

¿Sabías que puedes añadir tus propios comandos al menú / de Claude en menos de un minuto? Cualquier archivo Markdown (.md) que guardes dentro de la carpeta .claude/commands/ de tu proyecto se convierte automáticamente en un comando que puedes invocar escribiendo /nombre-del-archivo.

Además, si dentro de tu archivo Markdown escribes la variable especial $ARGUMENTS, Claude la sustituirá por el texto que escribas detrás del comando. Veamos un ejemplo real para este mismo proyecto web:


# Archivo: .claude/commands/nuevo-componente.md
---
description: Crea un nuevo componente WebComponent y lo registra en el sidebar e imports
---

Sigue las reglas de @README.md para crear un nuevo componente con estos datos: $ARGUMENTS

1. Crea la carpeta, el archivo .html y el archivo .js usando createComponent().
2. Asegúrate de que el título principal lleve class="title" y las tablas lleven
   class="table table-striped table-hover".
3. Registra el import en @js/components-imports.js y enlázalo en el sidebar.json correspondiente.
Ejemplo de comando personalizado guardado en .claude/commands/nuevo-componente.md.

Una vez guardado ese archivo, en el chat de Claude solo tendrás que escribir:


# Cómo invocarías tu nuevo comando personalizado desde el chat:
/nuevo-componente dentro de la vista gemini llamado "casos-practicos" sobre ejemplos de uso
Invocación del comando personalizado pasando argumentos dinámicos a $ARGUMENTS.

3. Skills (Habilidades) en Claude (.claude/skills/)

Además de los comandos que tú invocas manualmente con /, Claude soporta exactamente el mismo concepto de Skills (Habilidades bajo demanda) que vimos en Antigravity, guardadas en la ruta .claude/skills/<nombre-skill>/SKILL.md (o globalmente en ~/.claude/skills/).

  • ¿Cuál es la diferencia entre un Comando (.claude/commands/) y una Skill (.claude/skills/)?
    • Un Comando lo disparas tú explícitamente escribiendo /mi-comando.
    • Una Skill tiene su propio directorio (donde puedes incluir scripts, plantillas y referencias) y Claude puede activarla por sí solo automáticamente cuando detecta que lo que le pides coincide con la descripción (description) del archivo SKILL.md, además de poder invocarla con /.
