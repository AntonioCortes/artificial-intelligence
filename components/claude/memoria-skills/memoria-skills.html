Memoria y Reglas del Proyecto en Claude (CLAUDE.md y .claude/rules/)

1. ¿Qué es el archivo CLAUDE.md y por qué es tan importante?

En el ecosistema de Claude, el archivo CLAUDE.md cumple exactamente la misma misión que GEMINI.md en Antigravity: es la memoria permanente de tu proyecto. Cada vez que abres Claude Code en tu carpeta de trabajo, lo primero que hace de forma automática es leer el archivo CLAUDE.md e inyectar sus instrucciones en su memoria antes de que escribas la primera palabra.

Como vimos en el apartado de comandos /, no necesitas siquiera escribir este archivo desde cero: basta con ejecutar /init para que Claude analice tu repositorio y cree un primer borrador completo que luego puedes retocar con /memory o añadiendo notas rápidas con el prefijo #.

2. Jerarquía de los 4 Niveles de Memoria en Claude Code

Archivo y Ruta ¿Se sube a Git? Para qué sirve cada uno
~/.claude/CLAUDE.md No (está en tu carpeta de usuario) Memoria Global Personal: Tus preferencias personales para todos los proyectos de tu ordenador (ej. "Respóndeme siempre en español, usa commits semánticos y explica los cambios").
./CLAUDE.md (o ./.claude/CLAUDE.md) Sí (compartido con el equipo) Memoria del Proyecto: Arquitectura de carpetas, cómo añadir nuevas vistas y componentes, clases CSS obligatorias, comandos de compilación y tests.
./CLAUDE.local.md No (se ignora automáticamente en Git) Memoria Local Privada: Rutas locales, puertos de prueba o notas específicas de tu máquina para este proyecto que no quieres subir al repositorio compartido.
.claude/rules/*.md Sí (opcional y modular) Reglas Modulares por Tema o Ruta: Permite dividir las normas de un proyecto grande en varios archivos pequeños dentro de .claude/rules/ (ej. frontend.md, api-backend.md, docker-devops.md).

3. Reglas Modulares Condicionales (.claude/rules/*.md con paths)

Una función muy potente para proyectos Full Stack o Monorepos es que los archivos dentro de .claude/rules/ pueden incluir una cabecera YAML con el campo paths. Así, una regla de estilos CSS solo se cargará cuando Claude toque archivos .css o .html, y una regla de Terraform solo se activará cuando edite archivos .tf:


---
paths:
  - "components/**/*.html"
  - "css/**/*.css"
---

# Reglas de Maquetación para Componentes Web
1. Todo título principal de componente debe llevar `<h1 class="title">`.
2. Todas las tablas deben usar `<table class="table table-striped table-hover">`.
3. Incluye siempre un `<span class="center-horizontal caption">` debajo de tablas e imágenes.
Ejemplo de regla modular en .claude/rules/estilos-web.md que solo se activa al trabajar sobre archivos HTML o CSS.

4. Importar otros archivos dentro de CLAUDE.md con @ruta

Dentro de cualquier archivo CLAUDE.md puedes incluir referencias a otros documentos de tu proyecto escribiendo @ruta/al/archivo.md para mantener tu archivo principal limpio y corto:


# Memoria Principal del Proyecto

Consulta la guía base de la plantilla en @README.md y el registro de vistas en @components/common/assets/constants.json.
