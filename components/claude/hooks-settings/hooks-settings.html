Hooks del Ciclo de Vida y Permisos en Claude (.claude/settings.json)

1. ¿Dónde se configuran los Permisos y los Hooks en Claude Code?

En Claude Code, tanto las reglas de seguridad de qué herramientas pueden ejecutarse sin preguntar (permissions) como los disparadores automáticos del ciclo de vida (hooks) se configuran en el archivo .claude/settings.json (que se sube a Git para compartirlo con el equipo), en .claude/settings.local.json (privado para tu máquina) o en ~/.claude/settings.json (global para tu usuario).

También puedes gestionarlos mediante menús interactivos dentro del chat escribiendo los comandos /permissions, /hooks o /config.

2. Configuración de Listas de Permisos (allow, ask y deny)

Para no tener que aprobar manualmente cada comando seguro que usas a diario (como npm run, git status o docker ps) y al mismo tiempo blindar archivos sensibles como .env, puedes definir reglas granulares con comodines (*):

Tipo de Regla Sintaxis de Ejemplo Qué efecto tiene
allow (Permitir siempre) "Bash(npm run *)", "Bash(git diff *)" Autoriza a Claude a ejecutar cualquier script de npm run o ver diferencias de Git automáticamente sin interrumpirte.
ask (Preguntar siempre) "Bash(git push *)", "Bash(docker compose up *)" Obliga a pedirte confirmación explícita antes de subir cambios al repositorio remoto o levantar contenedores.
deny (Bloquear siempre) "Read(./.env*)", "Bash(rm -rf *)", "Bash(kubectl delete *)" Prohíbe terminantemente que Claude lea tus archivos de secretos .env o ejecute comandos destructivos.

3. Eventos de Hooks en Claude Code (PreToolUse, PostToolUse, Stop...)

Los Hooks en Claude Code te permiten ejecutar comandos de consola, peticiones HTTP o incluso evaluaciones rápidas con un prompt de IA en momentos clave de la sesión:

Evento del Hook Cuándo se ejecuta Caso de uso típico en Desarrollo y DevOps
PreToolUse Antes de que Claude ejecute una herramienta (ej. Bash, Edit, Write). Validar argumentos o bloquear ediciones en archivos protegidos (si el script devuelve código de salida 2, bloquea la acción y le muestra el error a Claude).
PostToolUse Inmediatamente después de que una herramienta se ejecute con éxito. Ejecutar automáticamente npx prettier --write, eslint --fix o terraform fmt cada vez que Claude edita o crea un archivo.
UserPromptSubmit Cuando envías un mensaje en el chat, antes de que Claude lo procese. Inyectar contexto dinámico o validar que no estás pegando claves secretas por error.
Stop / SubagentStop Cuando el agente principal o un subagente termina su respuesta. Comprobar que los tests pasan antes de permitir que dé la tarea por finalizada.
SessionStart / Notification Al arrancar la sesión o cuando Claude necesita tu atención. Enviar una notificación de escritorio o sonido cuando Claude termina una tarea larga.

4. Ejemplo Completo de archivo .claude/settings.json


{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff *)"
    ],
    "ask": [
      "Bash(git push *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Read(./.env*)"
    ]
  },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write ."
          }
        ]
      }
    ]
  }
}
