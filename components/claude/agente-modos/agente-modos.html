El Agente de Claude, Herramientas Nativas y todos sus Modos de Ejecución

1. ¿Cómo trabaja el Agente en Claude Code y qué Herramientas Nativas tiene?

Cuando abres Claude Code en tu proyecto (ya sea desde la terminal escribiendo claude o usando la extensión oficial en VS Code / Cursor / JetBrains), no estás ante un simple chat de texto: estás frente a un agente autónomo con herramientas integradas que puede inspeccionar, modificar y verificar tu proyecto por sí mismo.

Sin que tengas que instalar nada adicional, el agente de Claude dispone de este catálogo completo de herramientas internas (Built-in Tools):

Herramienta Nativa Qué hace exactamente ¿Requiere confirmación en modo Normal?
Read Lee el contenido de cualquier archivo de código, texto, imagen, PDF o cuaderno Jupyter (.ipynb) de tu proyecto. No (lectura segura automática).
Glob y Grep Busca archivos por patrón de nombre (Glob) o encuentra en milisegundos en qué línea exacta aparece una función o texto (Grep con expresiones regulares). No (lectura segura automática).
Edit y Write Modifica bloques exactos de líneas en archivos existentes (Edit) o crea archivos y carpetas nuevos desde cero (Write). Sí (muestra las diferencias en verde y rojo antes de guardar, salvo en modo acceptEdits o auto).
NotebookEdit Reemplaza, inserta o elimina celdas específicas dentro de cuadernos Jupyter (.ipynb). Sí (pide confirmación de edición).
Bash Ejecuta comandos en tu terminal: lanzar tests, git status, compilar proyectos, validar JSON o iniciar servidores en segundo plano. Sí (pide permiso para el comando o te permite autorizar ese prefijo para siempre).
WebSearch y WebFetch Busca información actualizada en Internet (WebSearch) o descarga y lee páginas de documentación técnica (WebFetch). Sí (al consultar dominios externos nuevos).
Agent (Subagentes / Task) Lanza subagentes especializados en paralelo (como el subagente rápido Explore para investigar el repositorio o el subagente Plan para diseñar arquitecturas) con su propia ventana de contexto aislada. Depende de las herramientas que utilice el subagente.
TodoWrite / AskUserQuestion Gestiona una lista de tareas visible en pantalla paso a paso (TodoWrite) o te plantea preguntas interactivas con opciones (AskUserQuestion) cuando hay varias decisiones de diseño posibles. No.

2. Los Modos Interactivos con Shift + Tab y todos los Modos de Permisos

Durante cualquier conversación en Claude Code, puedes pulsar la combinación de teclas Shift + Tab para rotar al instante entre los modos de trabajo interactivos, o bien configurar cualquiera de los 6 modos de permisos oficiales mediante el comando /permissions, el archivo settings.json o la bandera de arranque --permission-mode <modo>:

Figura 1. Los modos principales de ejecución de Claude Code y el flujo recomendado pasando de Plan Mode a Auto-Accept Edits.
Modo (permissionMode) Cómo activarlo Comportamiento detallado y cuándo usarlo
default (Modo Normal) Por defecto al abrir claude o rotando con Shift + Tab. Con confirmación paso a paso: Lee archivos libremente, pero cada vez que quiere editar un archivo o ejecutar un comando en consola se detiene, te muestra el cambio en pantalla y te pregunta si lo apruebas.
plan (Modo Planificación) Pulsando Shift + Tab, escribiendo /plan o con --permission-mode plan. 100% Solo Lectura: Claude investiga tu proyecto en profundidad, pero tiene prohibido modificar archivos o ejecutar comandos destructivos hasta que te presente un plan detallado y tú lo apruebes.
acceptEdits (Auto-Accept Edits) Pulsando Shift + Tab o con --permission-mode acceptEdits. Edición automática de archivos: Acepta y aplica automáticamente todas las creaciones y ediciones de archivos del proyecto sin interrumpirte, pero sigue pidiendo confirmación antes de ejecutar comandos delicados en la terminal.
auto (Modo Automático con Clasificador) Con --permission-mode auto o en /permissions. Clasificador inteligente de seguridad: Evalúa automáticamente en segundo plano cada acción o comando según reglas de seguridad (allow, soft_deny, hard_deny), ejecutando sin preguntar las operaciones seguras de desarrollo y bloqueando o consultando solo las arriesgadas.
dontAsk Con --permission-mode dontAsk. No interrumpir con diálogos: Ejecuta automáticamente todas las herramientas que ya estén pre-autorizadas en tus reglas de permisos (allow) y deniega silenciosamente cualquier herramienta no autorizada en lugar de detenerse a preguntar. Ideal para tareas desatendidas seguras.
bypassPermissions Con --permission-mode bypassPermissions o --dangerously-skip-permissions. Sin restricciones (Solo para contenedores / máquinas virtuales aisladas): Salta absolutamente todas las comprobaciones de permisos tanto de archivos como de terminal. Advertencia: úsalo únicamente en entornos sandbox o Docker sin acceso a datos sensibles.

3. Ejemplo práctico del flujo "Primero Planificar, Luego Ejecutar"

Así es como se ve una sesión real aplicando el método profesional de dos pasos en Claude Code:


# PASO 1: Pulsas Shift+Tab para activar [Plan Mode] (o escribes /plan) y pides tu tarea:
> Lee @README.md y traza un plan para añadir una vista de Gemini y otra de Claude
  en la barra de navegación superior, con sus respectivos apartados en el sidebar.

# Claude investiga los archivos sin modificar nada y te responde:
  "He leído README.md, constants.json y sidebar.js. Propongo este plan:
   1. Crear carpetas components/gemini y components/claude con common/assets/
   2. Crear los componentes WebComponent (.html y .js) y sus diagramas SVG
   3. Registrar todo en js/components-imports.js y constants.json
   ¿Quieres que proceda con este plan?"

# PASO 2: Pulsas Shift+Tab para pasar a [Auto-Accept Edits] y dices:
> Adelante, ejecuta el plan completo.
Flujo recomendado en dos pasos: acordar primero el diseño en Plan Mode y ejecutarlo después en Auto-Accept Mode.
