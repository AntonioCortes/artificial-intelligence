Servidores MCP, Hooks, Plugins y Sandbox

1. ¿Qué es un MCP (Model Context Protocol)? Explicado sin tecnicismos

Si nunca has oído hablar de MCP (Model Context Protocol o Protocolo de Contexto de Modelos), la forma más fácil de entenderlo es con una analogía cotidiana: MCP es como el puerto USB-C universal para la Inteligencia Artificial.

Antes de que existiera el estándar MCP, la IA solo podía leer los archivos de tu carpeta local. Si querías que la IA consultara una tabla de tu base de datos PostgreSQL, leyera un ticket de Jira, revisara los Pull Requests pendientes en GitHub o buscara un mensaje en Slack, no tenía forma directa de conectarse a esos programas. Con MCP, tú configuras pequeños conectores llamados Servidores MCP y, automáticamente, tu agente gana "superpoderes" (nuevas herramientas) para hablar con bases de datos, APIs y servicios externos de forma segura.

1.1. ¿Cómo se configura un Servidor MCP en Antigravity (mcp_config.json)?

En Antigravity, los servidores MCP se declaran en el archivo global ~/.gemini/config/mcp_config.json (o dentro de un plugin). Existen dos formas de conectar un servidor MCP:

  • Transporte Stdio (Local): El agente ejecuta un programa instalado en tu propio ordenador (por ejemplo, con Node.js o Python) y se comunica con él localmente.
  • Transporte Streamable HTTP (Remoto): El agente se conecta a una dirección web (url) de un servidor MCP remoto en la nube o en tu empresa.

{
  "mcpServers": {
    "base-datos-local": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sqlite", "/ruta/a/mi-base-datos.db"],
      "env": {
        "DB_READONLY": "true"
      }
    },
    "servidor-empresa-remoto": {
      "url": "https://mcp.miempresa.com/mcp"
    }
  }
}
Ejemplo de archivo mcp_config.json configurando un servidor MCP local por Stdio y otro remoto por HTTP.

2. ¿Qué son los Hooks (hooks.json) y para qué sirven?

Un Hook (Gancho de Ciclo de Vida) es un script o comando automático que tú programas para que se dispare exactamente antes o después de que el agente haga una acción, sin depender de que el agente "se acuerde" de hacerlo.

Por ejemplo: ¿quieres que siempre que el agente edite un archivo se pase automáticamente un comprobador de código (linter)? ¿O quieres prohibir que el agente pueda ejecutar jamás un comando peligroso en la terminal? Para eso se crea el archivo .agents/hooks.json:

Evento del Hook Cuándo se dispara exactamente Ejemplo práctico de uso
SessionStart Una sola vez al iniciar una conversación nueva. Inyectar un mensaje de bienvenida o comprobar que el entorno de desarrollo está levantado.
PreToolUse Justo antes de que el agente ejecute una herramienta (ej. run_command). Bloquear comandos peligrosos ("decision": "deny"), obligar a pedir permiso ("ask") o reescribir argumentos ("overwrite").
PostToolUse Justo después de que una herramienta termine de ejecutarse. Ejecutar automáticamente un formateador de código o un linter tras cada cambio.
PreInvocation / PostInvocation Antes o después de cada llamada al modelo de lenguaje. Inyectar recordatorios efímeros (ephemeralMessage) antes de que el modelo responda.
Stop Cuando el agente intenta dar por terminada su tarea y detenerse. Comprobar si los tests siguen fallando y, si es así, devolver "decision": "continue" para obligarle a seguir arreglándolo.

{
  "verificar-seguridad-comandos": {
    "PreToolUse": [
      {
        "matcher": "run_command",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/auditar-comando.sh",
            "timeout": 10
          }
        ]
      }
    ]
  }
}

3. Plugins (plugin.json): Cómo empaquetarlo todo para tu equipo

Si has creado varias Reglas, varias Skills, unos cuantos Hooks y una configuración de Servidores MCP y quieres compartir todo ese "kit de superpoderes" con tus compañeros de trabajo en una sola unidad, puedes crear un Plugin dentro de .agents/plugins/<nombre-plugin>/:


.agents/plugins/kit-desarrollo-web/
├── plugin.json        # Manifiesto obligatorio: { "name": "kit-desarrollo-web" }
├── mcp_config.json    # Servidores MCP que activa este plugin
├── hooks.json         # Hooks de ciclo de vida del plugin
├── rules/
│   └── AGENTS.md      # Reglas consolidadas del plugin
└── skills/
    └── crear-vista/
        └── SKILL.md   # Habilidades incluidas en el plugin
Estructura completa de un Plugin en Antigravity que agrupa reglas, skills, hooks y MCP.

4. Resumen comparativo: ¿Cuándo uso Rule, Skill, Hook, MCP o Plugin?

Si lo que necesitas es... Debes usar... Archivo donde se configura
Que la IA respete siempre el estilo y normas de tu código Rule (Regla) GEMINI.md o AGENTS.md
Enseñarle una receta paso a paso para una tarea concreta sin gastar memoria siempre Skill (Habilidad) .agents/skills/<nombre>/SKILL.md
Conectar la IA con una base de datos, GitHub, Jira o servicio externo MCP Server ~/.gemini/config/mcp_config.json
Ejecutar un script validador antes o después de que el agente use una herramienta Lifecycle Hook .agents/hooks.json
Empaquetar todo lo anterior para activarlo, desactivarlo o compartirlo Plugin .agents/plugins/<nombre>/plugin.json
