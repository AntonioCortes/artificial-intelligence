Plugins en Antigravity: Qué son, Cómo Funcionan y Cómo Crearlos

1. ¿Qué es exactamente un Plugin en Google Antigravity y qué hace?

Hasta ahora hemos visto que puedes personalizar tu agente con piezas individuales: Reglas (GEMINI.md / AGENTS.md), Skills (SKILL.md), Hooks (hooks.json) y Servidores MCP (mcp_config.json). Pero ¿qué pasa si quieres instalar de golpe un "kit completo de DevOps con Kubernetes" o un "kit completo de desarrollo Full Stack" que incluya al mismo tiempo sus servidores MCP, sus skills paso a paso, sus reglas de código y sus hooks de validación?

Para eso existen los Plugins. Un Plugin es un paquete todo-en-uno con su propio espacio de nombres (namespace) que agrupa Skills + Reglas + Hooks + Servidores MCP dentro de una única carpeta distribuible (.agents/plugins/<nombre>/ o ~/.gemini/config/plugins/<nombre>/). Cuando instalas o activas un plugin, Antigravity realiza tres acciones automáticas:

  1. Ingesta Automática (Automatic Ingestion): Carga al instante todos los servidores MCP definidos en el mcp_config.json del plugin, registra sus hooks de hooks.json, fusiona sus reglas de rules/AGENTS.md y añade sus skills/ al catálogo bajo demanda.
  2. Aislamiento de Nombres (Namespacing): Evita colisiones de nombres si dos plugins distintos incluyen herramientas o skills con nombres parecidos.
  3. Activación o Desactivación con un solo comando: Puedes encender o apagar todo el paquete con /plugins o agy plugin enable / disable (lo cual guarda el estado en tu config.json) sin tener que borrar ningún archivo.

2. La Triple Compatibilidad de Antigravity: Plugins Nativos, Gemini CLI y Claude Code

Una ventaja enorme de Google Antigravity (agy) es que su instalador de plugins (agy plugin install y agy plugin import) es compatible con tres formatos distintos:

Formato de Plugin Archivo de Manifiesto Cómo lo procesa Antigravity
1. Plugin Nativo Antigravity plugin.json, .antigravity-plugin/plugin.json o .gemini-plugin/plugin.json Se carga de forma directa leyendo skills/, rules/AGENTS.md, hooks.json (en la raíz del plugin) y mcp_config.json.
2. Extensión de Gemini CLI gemini-extension.json Al ejecutar agy plugin install, Antigravity importa la extensión y adapta su estructura automáticamente.
3. Plugin de Claude Code .claude-plugin/plugin.json Al ejecutar agy plugin install (o agy plugin import claude), Antigravity prepara automáticamente sus archivos (por ejemplo, mueve hooks/hooks.json a la raíz hooks.json) e importa sus skills, reglas y servidores MCP.

3. Comandos para Gestionar tus Plugins (/plugins y agy plugin)


# 1. Dentro del chat interactivo de Antigravity (TUI), escribe:
/plugins                                    # Abre el gestor visual de plugins instalados
/reload                                     # Recarga plugins, skills y reglas en caliente

# 2. Desde tu terminal de Linux/macOS usando los subcomandos de agy:
agy plugin list                             # Lista todos los plugins descubiertos y su estado (enabled/disabled)
agy plugin install ./ruta/a/mi-plugin       # Instala un plugin nativo, extensión Gemini o plugin de Claude
agy plugin import claude                    # Importa plugins desde tu configuración de Claude Code
agy plugin enable nombre-del-plugin         # Activa un plugin (guarda "enabled": true en config.json)
agy plugin disable nombre-del-plugin        # Desactiva un plugin sin desinstalarlo
agy plugin validate ./ruta/a/mi-plugin      # Verifica que la estructura y JSON del plugin sean válidos
agy plugin uninstall nombre-del-plugin      # Elimina un plugin instalado
Comandos interactivos y de consola para listar, instalar, importar, validar, activar y desactivar plugins.

4. Cómo Crear tu Propio Plugin Paso a Paso (plugin.json y plugins.json)

Crear un plugin para ti o para tu equipo de desarrollo es tan sencillo como crear una subcarpeta dentro de .agents/plugins/ con un archivo plugin.json:


.agents/plugins/fullstack-devops-kit/
├── plugin.json              # Obligatorio: { "name": "fullstack-devops-kit" }
├── mcp_config.json          # Opcional: Conecta Postgres, Playwright y Docker automáticamente
├── hooks.json               # Opcional: Ejecuta linter tras editar y bloquea comandos peligrosos
├── rules/
│   └── AGENTS.md            # Opcional: Reglas consolidadas de arquitectura Full Stack y DevOps
└── skills/
    ├── auditoria-docker/
    │   └── SKILL.md         # Opcional: Checklist para Dockerfiles multi-stage y docker-compose
    └── revision-api/
        └── SKILL.md         # Opcional: Checklist para endpoints REST, validación y tests
Estructura oficial de carpetas de un Plugin en Google Antigravity.

Además, si guardas tus plugins en una carpeta compartida fuera de .agents/plugins/, puedes registrarlos mediante el archivo .agents/plugins.json usando exactamente el mismo formato de entries, inherits, include_only y exclude que vimos en skills.json.
