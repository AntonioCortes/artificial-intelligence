Hooks del Ciclo de Vida (hooks.json) en Google Antigravity

1. ¿Qué son los Hooks (hooks.json) y por qué son diferentes de las Reglas?

En el apartado de Reglas (GEMINI.md) vimos que puedes pedirle al agente por escrito cosas como: "Por favor, ejecuta siempre el linter después de editar un archivo". Sin embargo, una regla de texto depende de que el modelo de IA la recuerde y decida seguirla. ¿Qué pasa si necesitas una garantía determinista al 100% (por ejemplo, bloquear siempre un comando peligroso en producción o pasar automáticamente un formateador de código tras cada edición)?

Para eso existen los Hooks (Ganchos del Ciclo de Vida). Un Hook es un script o comando automático que tú configuras en el archivo .agents/hooks.json (o en el global ~/.gemini/config/hooks.json) para que el sistema de Antigravity lo ejecute obligatoriamente antes o después de una acción concreta del agente.

2. Todos los Eventos del Ciclo de Vida soportados en hooks.json

Evento del Hook Cuándo se dispara exactamente Qué puede hacer tu script en ese momento
SessionStart Una sola vez al iniciar una conversación nueva. Comprobar que Docker o la base de datos local están levantados o inyectar variables de contexto iniciales.
PreToolUse Justo antes de que el agente ejecute una herramienta (ej. run_command, edit_file, write_file). Permitir ("allow"), bloquear ("deny"), obligar a pedir confirmación al usuario ("ask") o incluso modificar los argumentos de la herramienta al vuelo ("overwrite").
PostToolUse Justo después de que una herramienta termine de ejecutarse. Ejecutar automáticamente Prettier, ESLint, terraform fmt o un validador de sintaxis sobre el archivo recién modificado.
PreInvocation Justo antes de cada llamada al modelo de lenguaje Gemini. Inyectar recordatorios efímeros (ephemeralMessage) para ese turno sin contaminar el historial permanente.
PostInvocation Justo después de que el modelo genere su respuesta. Registrar métricas de auditoría o validar el contenido generado.
Stop Cuando el agente intenta dar por terminada su tarea y detenerse. Ejecutar la suite de tests o el compilador; si algún test falla, el hook devuelve "decision": "continue" con el error para obligar al agente a arreglarlo antes de parar.

3. Ejemplo Práctico de .agents/hooks.json para Full Stack y DevOps

En este ejemplo configuramos dos hooks muy útiles: uno en PreToolUse que audita los comandos de terminal antes de ejecutarlos, y otro en Stop que verifica que todos los archivos JSON y componentes del proyecto sean válidos antes de que el agente dé por terminada su respuesta:


{
  "seguridad-y-calidad-equipo": {
    "PreToolUse": [
      {
        "matcher": "run_command",
        "hooks": [
          {
            "type": "command",
            "command": "./scripts/auditar-comando-devops.sh",
            "timeout": 10
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "npm test",
            "timeout": 60
          }
        ]
      }
    ]
  }
}
Ejemplo real de archivo .agents/hooks.json combinando un guardarraíl preventivo (PreToolUse) y un verificador final (Stop).

4. Cómo responde un Script de Hook (Protocolo JSON por stdin y stdout)

Cuando Antigravity dispara tu script de hook, le envía por la entrada estándar (stdin) un objeto JSON con todos los detalles de la herramienta que se va a ejecutar (nombre de la herramienta, argumentos, directorio actual, ID de sesión). Tu script solo tiene que imprimir por salida estándar (stdout) un JSON indicando su decisión:


{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "Bloqueado por seguridad: no se permite ejecutar kubectl delete en el namespace de producción."
  }
}
Respuesta JSON de un hook en PreToolUse bloqueando un comando destructivo y explicando el motivo al agente.
