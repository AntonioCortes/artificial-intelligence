Cómo escribir buenos Prompts y guiar al Agente

1. La regla de oro: La IA no lee tu mente, lee tu contexto

Aunque los modelos modernos como Gemini y Claude son extraordinariamente inteligentes, el error número uno cuando empezamos a usarlos es dar instrucciones vagas de tres palabras esperando que adivinen cómo está montado nuestro proyecto, qué estilo visual preferimos o a quién va dirigido el texto. Aprender a formular buenas instrucciones (lo que se conoce como Prompt Engineering o Ingeniería de Prompts) multiplica por diez la calidad de los resultados.

Un prompt excelente no tiene por qué ser un texto literario complicado; simplemente debe responder con claridad a cinco preguntas clave:

  1. Contexto (¿Dónde estamos?): Explica brevemente qué es el proyecto o qué archivos debe leer primero para situarse (por ejemplo: "Este proyecto es una plantilla web SPA con WebComponents; lee primero el archivo @README.md").
  2. Objetivo (¿Qué quieres conseguir?): Define con precisión qué quieres que cree, modifique o explique.
  3. Audiencia o Nivel (¿Para quién es?): Si pides explicaciones o documentación, indica para quién es (por ejemplo: "Explícalo para alguien que empieza desde cero y no sabe qué es un MCP ni una Skill").
  4. Restricciones y Reglas (¿Qué NO debe hacer o cómo debe estructurarlo?): Por ejemplo: "No pongas toda la información en un solo componente; desglósalo en distintos apartados en el sidebar y respeta las clases CSS del README".
  5. Modo de trabajo (¿Planificar primero o ejecutar?): Indícale si quieres que primero diseñe un plan de ejecución y luego lo implemente, o si debe hacerte preguntas antes de empezar.

Observa cómo cambia radicalmente lo que la IA entiende según cómo le pidas la misma tarea:

3. Plantilla práctica para pedir tareas complejas a un Agente

Cuando quieras que el agente de Gemini (Antigravity) o Claude realice un trabajo grande en tu proyecto, puedes seguir esta estructura que nunca falla:


# 1. CONTEXTO E INVESTIGACIÓN PREVIA
Lee primero @README.md y revisa la carpeta @components/main-view/ para entender
cómo se estructuran las vistas, los WebComponents y los estilos de esta página.

# 2. OBJETIVO PRINCIPAL
Quiero crear una nueva vista llamada "Docker" en la barra de navegación superior
que enseñe a usar contenedores desde cero hasta Docker Compose.

# 3. REQUISITOS Y RESTRICCIONES
- Divide el contenido en 4 componentes separados dentro de su sidebar.json.
- Incluye ejemplos de archivos Dockerfile y docker-compose.yml reales.
- Genera diagramas en formato SVG para explicar la diferencia entre Imagen y Contenedor.
- Respeta estrictamente las clases CSS (.title, .center-horizontal, .caption, tablas).

# 4. FLUJO DE EJECUCIÓN
Primero elabora un plan de ejecución detallado y, una vez lo tengas claro, ejecútalo
y verifica que todos los componentes estén importados en @js/components-imports.js.
Plantilla reutilizable en cuatro bloques para encargar desarrollos completos al agente.

4. Cinco trucos profesionales para trabajar con Agentes

  • Apunta a los archivos con @: Siempre que sepas qué archivo contiene las reglas o el código a modificar, menciónalo con @nombre-archivo. Así el agente va directo al grano en el segundo 1.
  • Pide ejemplos y contraejemplos: Si estás aprendiendo algo con la IA, pídele siempre: "Muéstrame un ejemplo de cómo se hace bien y otro de un error típico que debo evitar".
  • Usa criterios de verificación: Si estás programando una aplicación con tests o un servidor, dile al final de tu prompt: "Cuando termines, ejecuta los tests en la terminal para comprobar que todo pasa en verde".
  • Corrige el rumbo a tiempo: Si ves en pantalla que el agente ha entendido mal un requisito mientras está trabajando, no hace falta que esperes diez minutos a que termine; puedes pararlo, aclararle el detalle y dejar que continúe con la idea corregida.
  • Convierte tus correcciones en Reglas permanentes: Si notas que en todos tus chats tienes que repetirle la misma norma (por ejemplo: "usa siempre comillas simples y escribe los comentarios en español"), guárdalo en el archivo GEMINI.md o CLAUDE.md de tu proyecto para que lo cumpla siempre de forma automática.
