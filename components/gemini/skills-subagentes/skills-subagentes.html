Skills (Habilidades) en Antigravity: Qué son y Cómo Crearlas

1. ¿Qué es una Skill (Habilidad) explicada desde cero?

Si nunca has escuchado la palabra Skill en inteligencia artificial, piensa en la película Matrix: cuando el protagonista necesita pilotar un helicóptero, le cargan un "paquete de conocimiento" específico justo en ese momento y aprende el procedimiento exacto en segundos. Antes de necesitarlo, ese manual no estaba ocupando espacio en su cabeza.

En Google Antigravity (y también en Claude), una Skill es una carpeta que contiene un manual paso a paso (llamado SKILL.md) junto con scripts de ayuda, plantillas o ejemplos para realizar una tarea especializada. ¿Por qué no meter todo en el archivo de reglas GEMINI.md? Porque si tienes 30 procedimientos largos (cómo desplegar en AWS, cómo crear migraciones de base de datos, cómo auditar accesibilidad, cómo generar informes PDF...) y los cargas todos siempre al iniciar el chat, gastarías toda la memoria (tokens) de la conversación antes de empezar.

Las Skills solucionan esto mediante un sistema llamado Progressive Disclosure (Revelación Progresiva):

  1. Al arrancar la conversación, el agente solo ve una lista muy cortita con el nombre y la descripción de 2 líneas de cada Skill disponible (puedes verlas todas escribiendo /skills).
  2. Cuando tú le pides algo relacionado con una de esas habilidades, el agente piensa: "¡Ajá! Para esta tarea existe la Skill X", y solo entonces abre y lee el archivo SKILL.md completo.
Figura 1. Funcionamiento de las Skills por carga progresiva bajo demanda (Progressive Disclosure).

2. ¿Cómo se crea una Skill paso a paso? Estructura de carpetas

Puedes crear tus propias Skills para tu proyecto dentro de la carpeta .agents/skills/ (para compartirlas con tu equipo en Git) o en ~/.gemini/config/skills/ (para tenerlas en todos los proyectos de tu ordenador). Cada Skill es una carpeta con esta estructura:


.agents/
└── skills/
    └── crear-vista-web/           # Nombre de la carpeta de tu Skill
        ├── SKILL.md               # OBLIGATORIO: Instrucciones principales con cabecera YAML
        ├── scripts/               # Opcional: Scripts ejecutables (.sh, .py, .js) de ayuda
        │   └── validar-json.sh
        ├── examples/              # Opcional: Archivos de ejemplo de referencia
        │   └── ejemplo-componente.html
        ├── resources/             # Opcional: Plantillas o logos base
        └── references/            # Opcional: Documentación extensa que solo se lee si hace falta
Estructura oficial de directorios de una Skill en Google Antigravity.

2.1. Ejemplo real de un archivo SKILL.md

Todo archivo SKILL.md debe empezar obligatoriamente con un bloque de cabecera entre tres guiones (---) llamado YAML Frontmatter que incluye únicamente dos campos: name (nombre en minúsculas con guiones) y description (explicación clara de qué hace la Skill y cuándo debe activarla el agente):


---
name: crear-vista-web
description: >-
  Guía paso a paso para crear una nueva vista en la barra de navegación superior
  con su logo SVG, su sidebar.json y sus componentes WebComponent. Activa esta
  skill siempre que el usuario pida añadir una nueva vista o tema al navbar.
---

# Procedimiento para Crear una Nueva Vista

Sigue estos pasos en orden estricto cuando el usuario solicite una nueva vista:

## Paso 1: Crear estructura de carpetas
1. Crea la carpeta `components/<nombre-vista>/common/assets/img/`.
2. Genera un icono vectorial en `components/<nombre-vista>/common/assets/img/logo.svg`.
3. Crea el archivo `components/<nombre-vista>/common/assets/sidebar.json` con las claves
   `pageContent` y `links`.

## Paso 2: Crear los componentes y registrarlos
1. Por cada apartado del sidebar, crea su subcarpeta con su `.html` y su `.js`.
2. Importa todos los archivos `.js` nuevos en `js/components-imports.js`.
3. Registra la nueva vista en `components/common/assets/constants.json`.
Ejemplo real de un archivo SKILL.md que enseña al agente un flujo de trabajo repetible.

3. Configuración Avanzada con skills.json y Orden de Prioridad

Si en tu empresa o equipo guardáis las Skills en carpetas no estándar o en repositorios compartidos fuera del proyecto, puedes declarar dónde buscarlas y cuáles filtrar creando el archivo .agents/skills.json (o el global ~/.gemini/config/skills.json):


{
  "inherits": [
    {
      "path": "/ruta/compartida/empresa/skills.json",
      "include_only": ["auditoria-seguridad", "estilo-corporativo"],
      "exclude": ["skill-antigua"]
    }
  ],
  "entries": [
    {
      "path": "tools/ia/skills",
      "exclude": ["experimental-.*"]
    },
    {
      "path": "~/mis-skills-personales"
    }
  ]
}
Archivo .agents/skills.json usando herencia (inherits) y filtros include_only / exclude.

Cuando Antigravity descubre varias Skills con el mismo nombre en distintas ubicaciones, aplica este orden de prioridad de mayor a menor:

  1. 1º Proyecto Actual (Workspace Discovery): .agents/skills/ dentro de tu repositorio.
  2. 2º Declaradas en el Proyecto: Rutas listadas en .agents/skills.json.
  3. 3º Globales de Usuario: ~/.gemini/config/skills/.
  4. 4º Integradas de Fábrica (Built-in): Como agy-customizations y antigravity-guide.
  5. 5º Declaradas en JSON Globales: Rutas listadas en ~/.gemini/config/skills.json.
