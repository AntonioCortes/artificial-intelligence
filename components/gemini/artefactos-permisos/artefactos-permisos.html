Artefactos, Sandbox, Permisos y Tareas en Segundo Plano

1. ¿Qué son los Artefactos (Artifacts) en Antigravity?

Cuando trabajas con el agente de Google Antigravity en una tarea grande, no sería cómodo que te soltara un informe de 500 líneas mezclado entre los mensajes cortos del chat, ni tampoco que te llenara la carpeta de tu proyecto de archivos temporales de borradores. Por eso existen los Artefactos (Artifacts).

Los Artefactos son documentos Markdown especiales (.md) que el agente crea y actualiza en una carpeta interna separada de tu código (brain/<id-conversacion>/) y que puedes ver cómodamente en el panel lateral de Antigravity. Sirven para:

  • Planes de Ejecución Interactivos: Cuando el agente diseña un plan antes de programar, puede presentártelo como un Artefacto ejecutable con un botón "Proceed" (Proceder) para que lo revises y le des luz verde con un clic.
  • Informes, Diagramas Mermaid y Carruseles: Dentro de los artefactos el agente puede incluir diagramas de flujo (mermaid), tablas comparativas, bloques de alerta destacados ([!NOTE], [!TIP], [!IMPORTANT], [!WARNING], [!CAUTION]), enlaces clicables a líneas exactas de tus archivos y carruseles de diapositivas (carousel).
  • Carpeta scratch/ para pruebas rápidas: Si el agente necesita crear un pequeño script temporal para probar algo o verificar unos datos sin ensuciar las carpetas de tu proyecto web, lo guarda dentro de brain/<id-conversacion>/scratch/.

2. ¿Qué es el Terminal Sandbox y cómo protege tu ordenador?

Una duda muy lógica cuando empiezas a usar agentes que ejecutan comandos en la terminal es: "¿Y si el agente se equivoca de comando y borra algo de otra carpeta de mi ordenador?". Para que puedas trabajar con total tranquilidad y sin tener que aprobar manualmente cada mínimo comando, Antigravity ejecuta los comandos dentro de una Caja de Arena segura (Terminal Sandbox):

  1. Modo Sandbox Estándar (Activo por defecto): Dentro del Sandbox, los comandos tienen permiso de lectura y escritura únicamente dentro de la carpeta de tu proyecto actual, en la carpeta de artefactos y en /tmp, y no tienen acceso a internet ni al resto de archivos privados de tu ordenador. Gracias a este aislamiento, el agente puede ejecutar pruebas, validar JSONs o listar archivos automáticamente sin interrumpirte para pedir permiso.
  2. Salir del Sandbox (Con tu permiso explícito): Si un comando concreto necesita obligatoriamente conectarse a internet (por ejemplo, para descargar paquetes con npm install) o levantar un puerto de red, el agente solicita ejecutar solo ese paso fuera del Sandbox y Antigravity te muestra un aviso claro para que lo apruebes.
  3. Aprobación Inteligente por Prefijo ("Always Allow"): Cuando apruebas un comando con la opción "Permitir siempre" (por ejemplo, apruebas npm test), Antigravity recuerda ese prefijo para que futuras ejecuciones de npm test ... no vuelvan a preguntarte.

3. Configuración de Permisos y Políticas (Global vs Por Proyecto)

Desde el panel de Settings (Ajustes) de Antigravity puedes personalizar el nivel de autonomía del agente tanto de forma global (para todo tu ordenador) como de forma específica para un proyecto concreto:

Ajuste / Política Opciones disponibles Qué controla
Tool Execution Policy proceed-in-sandbox, request-review, always-proceed, strict Define si los comandos de terminal se ejecutan solos dentro del sandbox, si piden siempre confirmación o si avanzan automáticamente.
Non-Workspace File Access allow, ask, deny Controla si el agente puede leer o editar archivos que estén fuera de la carpeta raíz de tu proyecto.
Internet Access Policy allow, ask, deny Controla si el agente puede realizar peticiones de red a internet.
Command Allowlist / Denylist Lista de comandos permitidos o bloqueados Te permite definir comandos de terminal que siempre están permitidos sin preguntar o que están terminantemente prohibidos.
Browser Allowlist Lista de dominios web Restringe a qué páginas o dominios puede navegar la herramienta de navegador del agente.
Artifact Review Mode always-proceed, agent-decides, asks-for-review Controla cuándo se detiene el agente para pedirte que revises un Artefacto (como un plan) antes de continuar.

4. Tareas en Segundo Plano (Background Tasks), Daemons y Despertar Reactivo

¿Qué pasa cuando el agente necesita arrancar un servidor web local (que se queda encendido indefinidamente) o ejecutar una batería de tests que tarda 3 minutos? En Antigravity el agente no se queda "congelado":

  • Paso automático a Background: Si un comando tarda más del tiempo de espera inicial, pasa automáticamente a ejecutarse como una Tarea en Segundo Plano (Background Task).
  • Procesos Daemon (Servidores en vivo): El agente puede arrancar servidores de desarrollo o vigilantes de archivos (watchers) en modo Daemon para que sigan corriendo en segundo plano mientras él sigue trabajando.
  • Despertar Reactivo (Reactive Wakeup): Ni tú ni el agente tenéis que estar preguntando cada 5 segundos si una tarea o un subagente ha terminado. En cuanto una tarea en segundo plano finaliza o un temporizador programado con /schedule se cumple, el sistema notifica y despierta automáticamente al agente con el resultado.
